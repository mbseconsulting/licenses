# Repository layout

The directory path forms the URL path. GitHub Pages serves the repository root at
`https://licenses.mbseconsulting.com/`, so `software/1.0.txt` resolves at
`https://licenses.mbseconsulting.com/software/1.0.txt`.

| Path | Role |
|---|---|
| `software/<version>.txt` | A published licence text. |
| `software/<version>-header.txt` | The file header notice for that version. |
| `CNAME` | Binds the GitHub Pages site to `licenses.mbseconsulting.com`. |
| `README.md` | States what the repository is and indexes the published versions. |
| `CLAUDE.md` | Guidance for Claude Code sessions in this repository. |
| `docs/` | This guide. |
| `.claude/`, `.github/` | Generated by the organisation conventions sync. |

## Branch protection

Two rulesets govern `main`.

| Ruleset | Rules | Bypass |
|---|---|---|
| `main: immutable history` | force-push blocked, deletion blocked, linear history | none |
| `main: require pull request` | pull request required, squash merge only, conversation resolution required | none |

No approving review is required, so either organisation owner merges their own pull request. Nobody,
including an owner, pushes to `main` directly or rewrites its history.

## Publishing

GitHub Pages deploys `main` from the repository root. The custom domain requires a DNS record at the
registrar:

```
licenses  CNAME  mbseconsulting.github.io
```

HTTPS is enforced, and GitHub issues the certificate automatically.
